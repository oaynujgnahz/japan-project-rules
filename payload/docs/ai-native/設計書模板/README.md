## 两种写法（选一）

| 模式 | 适用 | 主文件 |
|------|------|--------|
| **拆分模式（推荐）** | 多画面、多 API、需 OpenAPI | `詳細設計書.md` + `06_画面設計書/` + `07_API設計書/` |
| **单体模式** | 小功能、1～2 个 API | `機能設計書.md`（§3=画面、§4=API，见模板内说明） |

## 标准目录结构

复制本文件夹内容到 `docs/{機能}/` 后按功能改名：

```text
docs/{機能}/
├── README.md                 ← README_機能索引_模板.md
├── 理解现状摘要.md            ← 可选；代码入口・表主键（流程见処理フロー詳細）
├── 処理フロー詳細.md          ← 推荐；業務記述全流程（見 設計書記述規範.md）
├── 验收标准.md               ← 复制 ../验收标准_模板.md
├── 詳細設計書.md             ← 詳細設計書_模板.md（拆分模式主文档）
├── 要件確認事項.md            ← 可选；TBD 范围用
├── 06_画面設計書/
│   └── SCR-{编号}_{名}.md    ← 06_SCR_画面設計書_模板.md
├── 07_API設計書/
│   ├── openapi.yaml          ← openapi_骨架.yaml
│   └── API-{编号}_{名}.md    ← 07_API_設計書_模板.md
└── 08_データモデル.md         ← 可选；表变更多时用
```

## 使用步骤

1. **确定機能名** → 创建 `docs/{機能}/`（一功能一文件夹）
2. **理解现状** → 填 `理解现状摘要_模板.md`（或跳过，直接写设计书）
3. **写设计书** → 复制模板；**処理フロー**按 [設計書記述規範.md](../設計書記述規範.md) 写 `処理フロー詳細.md`
4. **验收标准** → 复制 `docs/ai-native/验收标准_模板.md`
5. **设计评审** → 对照 `.cursor/rules/review.mdc`；画面改修另见 `ppt-first-ui.mdc`
6. **功能开发** → 代码变更后回写设计书「実装状態」列

## 记号

| 记号 | 含义 |
|------|------|
| ○ | 必填 |
| △ | 条件必填 |
| × | 不传 / 不复制 / 不做 |
| ⏳ | 设计有、实装未完成 |
| ✅ | 已实装 |

## 与 AI Native 流程的关系

| 阶段 | 用哪些模板 |
|------|------------|
| 理解现状 | `理解现状摘要_模板.md` |
| 写设计书 | 本文件夹全套 + `验收标准_模板.md` + **`設計書記述規範.md`** |
| 设计评审 | 对照 `review.mdc`，不强制改模板 |
| 功能开发 | 回写 `実装状態`；画面用 `ppt-first-ui.mdc` |

**模板是填空指南，不是对话协议。** 可直接用自然语言让 Agent「按 `docs/ai-native/設計書模板/` 为 {機能} 建设计书」。
